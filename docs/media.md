# Media imports — Step 2.4

Apply migrations 0006 and 0007 after 0001–0005. Migration 0006 creates private `media-uploads`, a 500 MiB bucket limit, owner Storage policies, server-written/owner-readable jobs, atomic claims, upload-reservation guards and an idempotent final commit. It publishes jobs through `supabase_realtime` when that publication exists. Check [actual local catalog results](2.4-rls-query-results.txt).

Set the project's global Storage upload limit to at least 500 MiB as well; the local config now uses 500MiB, and your hosted plan must allow that size. Enable Storage and Realtime locally; the previous slim stack excluded those services. Keep normal Auth/Storage CORS configured for the app's origin. Uploads go browser → signed private Storage URL, so the media bytes never pass through a Vercel upload function. The worker validates the actual duration, codec and byte length after download, not a client-supplied claim.

See [worker setup](../worker/README.md) for Render/Docker instructions and secrets. The app needs WORKER_URL and WORKER_SECRET, in addition to the existing Supabase server credentials and Upstash settings. The worker needs APP_URL, WORKER_SECRET and OPENAI_API_KEY. No Anthropic key is needed. A Supabase service-role key cannot be genuinely scoped to one bucket, so the worker receives no service key: an HMAC-protected app interface restricts it to the private job's object and validated extraction.

The browser shows direct-upload progress and a live job card. Realtime updates are backed by polling, and the current job survives a reload in local storage. Review produces the same canonical columns as document imports, then uses mapping → preview → commit. Every media row has timestamp playback and the source panel can refresh the signed URL before playing. The original remains private during review; only after successful commit are the rows final and the source object deleted. Temporary worker files are removed earlier. An upload-reservation trigger prevents an unexpired signed upload token recreating a confirmed file after deletion.

The 500 MB and 30-minute limits are configuration/schema/probe-checked; tests use small synthetic two-minute fixtures, not a 500 MB performance benchmark. Actual ffmpeg and the final Node 20 Docker image were tested. Local Supabase/Storage/Redis tests cover both fixture lifecycles and owner isolation, while browser tests cover actual signed uploads, progress/reload, review, signed timestamp playback and deletion. Controlled speech/AI results are not claimed as a real Whisper run. OPENAI_API_KEY and a deployed worker are not configured in this cloud runtime, so paid end-to-end transcription and hosted deployment remain unverified.
