# Insights — Step 2.5

`lib/costs/anomalies.ts` is pure. It uses `rowVariancePct` from calc.ts, population standard deviation and linearly interpolated quartiles (type 7). Threshold comparisons are strict: more than two deviations, greater than Q3 + 1.5 IQR, and greater than 25% of group actual. Missing/zero baselines do not enter percentage statistics. Statistics, group totals and duplicate matching are separated by currency. Duplicate matching normalizes item case/spacing and uses the actual amount (or estimate when actual is absent), cents, date and currency. Null dates compare as null. All duplicate candidates are flagged. Non-concentration rules are high priority; concentration alone is medium. These are review signals, not proof of an error.

The summary route is POST `/api/projects/[id]/ai/summarise`. It accepts only validated filter/regeneration controls. It authorizes the project and loads the cost rows itself; clients cannot supply totals, prompts, models or another user's rows. Payload totals/groups/categories come from calc.ts. At most 40 prioritized flags are explained per view; all flags remain available in the table. Opaque row aliases are sent to the model and translated back after validation, so no user/project/database row IDs are exposed in the prompt. Text passes the existing privacy masking and untrusted-data framing.

The response schema enforces 150–200 summary words, 3–5 findings, exactly three recommendations and one explanation per supplied flag. The smart role is configurable via GEMINI_MODEL_SMART; the default is the responsive `gemini-flash-lite-latest` alias, also used by the fast role. Larger Flash aliases timed out on this account during live image checks, while this alias returned validated text and receipt extraction within the existing 60-second bound. No automatic provider/model fallback bypasses the configured allow-list.

A canonical hash of every loaded row participates in the private cache key, even when the edited row is not flagged. Migration 0007 uses statement transition tables to invalidate a project's summary cache after inserts, updates or deletes, including bulk imports. Fingerprints prevent concurrent stale writes from becoming current cache hits. Regenerate skips a cache read but retains quotas, privacy, schema validation and auditing. The gateway returns the original generation timestamp for cache hits.

The dashboard shows insights on the right at wide widths and in an AI insights tab on mobile. Rule flags appear immediately; generating AI explanations is explicit. Clicking a flag switches back to the dashboard, removes chart focus, selects the correct table page, highlights the row and scrolls it into view. Anomalies-only filtering is stored in the URL and affects the table, keeping the KPI/chart cohort intact. Changed cost rows/filter scopes discard the old displayed summary. Generated text is rendered as text, never HTML.

Report code can call `summariseProject` in cached mode, revalidating current ownership/data/privacy without creating a paid model request on a GET download. The report preview's explicit POST generation prepares that section first.
